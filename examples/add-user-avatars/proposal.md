# 添加用户头像功能

## 动机

当前用户系统只有文本信息（用户名、邮箱），缺少视觉识别元素。用户反馈希望能够：
1. 上传个人头像，增强个人主页的表现力
2. 在评论、消息等场景中看到其他用户的头像，提升社交体验
3. 快速识别用户身份，而不需要阅读用户名

数据显示，有个人头像的用户的活跃度比无头像用户高 40%。

## 变更范围

### 新增能力

- `avatar-upload`: 用户可以上传 JPEG/PNG 格式的头像图片
- `avatar-display`: 在个人主页、评论列表、消息界面显示用户头像
- `avatar-validation`: 验证图片格式、尺寸、文件大小
- `default-avatar`: 为未上传头像的用户生成默认头像（基于用户名首字母）

### 修改能力

- `user-profile`: 个人资料页新增头像上传和预览功能
- `user-api`: `/api/users/:id` 响应中包含 `avatar_url` 字段

### 不在范围内

- ❌ 头像编辑功能（裁剪、滤镜等）- 用户可以在上传前自行编辑
- ❌ 多头像切换 - 只支持一个头像
- ❌ 头像历史记录 - 上传新头像会替换旧头像
- ❌ 第三方头像导入（Gravatar 等）- 未来可考虑

## 影响分析

### 向后兼容性

✅ **完全兼容**

- 新增字段 `avatar_url`，旧客户端忽略此字段
- API 版本保持不变
- 旧用户数据不需要迁移（使用默认头像）

### 性能影响

**存储**:
- 预期平均每个头像 100KB
- 10,000 用户 ≈ 1GB 存储
- 使用对象存储（S3/OSS），成本可控

**带宽**:
- 头像会被 CDN 缓存
- 首次加载后对服务器带宽影响极小

**数据库**:
- `users` 表新增一个 `avatar_url` 字段（VARCHAR(255)）
- 影响可忽略

### 安全考虑

**潜在风险**:
- 用户上传不当图片（色情、暴力、版权）
- 恶意上传超大文件消耗存储

**缓解措施**:
- 文件大小限制：5MB
- 格式限制：仅 JPEG/PNG
- 内容审核：接入图片审核 API（一期可选，二期必需）
- 用户上传频率限制：每天最多修改 3 次

### 依赖变化

**新增依赖**:
- 对象存储 SDK（AWS S3 或 阿里云 OSS）
- 图片处理库（用于生成缩略图）

**无移除依赖**

## 成功标准

- [ ] 用户可以上传 JPEG/PNG 头像，文件大小 ≤ 5MB
- [ ] 上传的头像在个人主页、评论、消息中正确显示
- [ ] 未上传头像的用户显示基于用户名的默认头像
- [ ] API 响应中包含 `avatar_url` 字段
- [ ] 上传头像的 P95 延迟 < 2 秒
- [ ] 所有相关页面的测试覆盖率 ≥ 80%

## 时间估算

- 设计：1 天
- 实现：3-4 天
- 测试和审查：1-2 天
- **总计**: 约 1 周
