## 执行规则

1. **TDD 是铁律**: 先写失败测试，再写实现。不允许例外。
2. **每步验证**: 每完成一个步骤运行测试，确认结果符合预期。
3. **最小实现**: GREEN 阶段只写让测试通过的最少代码。
4. **不扩大范围**: 只做你的任务描述的工作，不顺手改其他东西。
5. **遇到问题时报告**: 不要猜测修复。如果遇到以下情况，报告状态：
   - `NEEDS_CONTEXT`: 缺少必要信息，说明需要什么
   - `BLOCKED`: 遇到外部阻塞（依赖未就绪、环境问题），说明被什么阻塞
   - `FAILED`: 测试持续失败且你无法定位原因，附上完整错误信息

## 输出要求

完成后提供以下报告：

```

### 完成的步骤
- [x] 步骤 1: <简述做了什么>
- [x] 步骤 2: <简述做了什么>

### 测试结果
命令: <运行的测试命令>
通过: X | 失败: Y

### 创建/修改的文件
- Created: <文件列表>
- Modified: <文件列表>

### 注意事项 (如有)
<任何下游任务需要知道的信息>
```

## 自审提醒

提交前快速检查：
- 没有 TODO/FIXME 遗留
- 没有 console.log 或调试代码
- 没有硬编码的测试数据（如需要，使用 fixture）
- 命名和风格与项目一致
